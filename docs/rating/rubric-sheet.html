0. Read this first: which "dimensions" exist

There are two documented human instruments, and they are different things.

  1. The approval rubric (docs/approval-rubric.md, v1.2): four gates of pass/fail checks, then one decision (approve / revise / reject). Fully documented: section A below.
  2. The quality rubric (PRD.md §7.1): a weighted list of dimensions. Only names, weights and "scored by" are documented. No definition, no scale. Section B below leaves those cells empty on purpose.

The memory score's components (S, P, C, A, F, E in Memory.md §3.1) are not on this sheet: they are numbers the software computes for a memory item against a search query. No person scores them.

A. The approval rubric

Source (docs/approval-rubric.md §1): The approver is judging one narrower question: "Would it be defensible to publish this?"  A campaign can be mediocre and still approved. A campaign can be brilliant and still rejected.

Source (§3): Evaluate in order. Stop at the first failed blocking gate and record that gate as the reason.

Amended 1 November 2026 (amendment A1, ruling 2): raters tick every check that failed, not only the first. The first failed gate is worked out afterwards from the order below (Gate 1, 2, 3, 4), and the outcome follows from that order as before.

Gate 1 — Truth (blocking). Any failure → reject. Record the failing sub-check.

OutcomeWhen
ApproveAll four gates pass

Source (§2, conduct): the rater approves, requests revision, or rejects. They never fix the output themselves. Raters are blind to arm; if the arm can be inferred (for example from an obviously empty evidence pack), record that in the notes.

C. Gaps found while building this sheet (before A1; the defects in A1's draft anchors are in rubric-amendment-1.md section 4)

  1. Five rated dimensions have no documented definition and no documented scale: product relevance, customer relevance, brand consistency, originality, feasibility. Trustworthiness has a method name and nothing else.
  2. The project asks for κ "per rubric dimension" (docs/evaluation-plan.md §6, D2). κ needs categories. Only the approval outcome (approve / revise / reject) and the pass/fail checks have them.
  3. The stored shape of a rater's scores is undocumented (campaigns.quality_scores is "jsonb, blind raters only").
  4. The approval rubric's example of a "Gate 3" failure needs a strategy and an evidence pack (C3.1, C3.3, C3.4); the practice pieces are copy only, so Gate 3 cannot be practised on them.
  5. S2.3 (required disclaimer) cannot be practised without a regulated product; no practice piece uses one, so as not to echo the evaluation's regulated brands.
